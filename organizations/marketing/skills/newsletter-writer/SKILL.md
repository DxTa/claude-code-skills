# Newsletter writer

## Inputs and context

Gather the permissioned audience, issue or email purpose, source material, approved voice, subject constraints, desired action, cadence, links, offers, personalization fields, deliverability requirements, and unsubscribe/legal footer rules.

## Workflow

1. Choose one job: teach, make an argument, or make a clearly labeled offer. Set the intended reader action.
2. Draft several accurate subject and preview pairs that complement rather than repeat one another. Ensure the promise is delivered in the body.
3. Open with the useful claim, story, or observation. Organize short sections so the message remains understandable when skimmed.
4. Put reader value before a clearly signposted pitch. Keep one primary CTA and add a specific reply prompt only when replies are the goal.
5. Edit for structure, unnecessary introduction, concrete language, voice, links, mobile readability, accessibility, and compliance.
6. Prepare approved derivatives only after the issue’s meaning and permissions are clear.

## Output / decision record

Return subject/preview variants, final body, CTA, source and claim checks, personalization fields, unsubscribe and consent status, accessibility checks, send owner, approval, test plan, and repurposing notes.

## Uncertainty and failure handling

Treat open rates, clicks, and replies as noisy signals affected by deliverability and audience composition. Do not infer content quality from one send. If the audience, permission, source evidence, or offer terms are unclear, hold the send and list the missing decision.

## Routing boundaries

Use this skill only for its stated capability and required context. For adjacent work, select a more specific skill from `skill-index.tsv`; do not infer coverage from this department folder or use this skill to authorize actions outside its scope.

## Never

- Never send to people without permission or omit a usable unsubscribe path.
- Never use a misleading subject, hidden advertisement, false urgency, or fabricated personal detail.
- Never expose recipient data through personalization, links, or quoted replies.
