# Revenue operations

A revenue process is useful only when definitions predict decisions and outcomes.

## Inputs and context

Collect current lifecycle and pipeline definitions, CRM fields and quality, routing/SLA data, closed-won/lost history, forecast snapshots, owners, handoff failures, and target measures.

## Workflow

1. Define each stage by observable buyer or account event, entry/exit evidence, owner, and stale-record rule.
2. Separate fit from intent in qualification and test both against historical outcomes before assigning action.
3. Specify handoff criteria, context payload, response SLA, rejection reason, and return route.
4. Enforce only fields used in decisions; audit duplicates, missing values, aging, stage conversion, and forecast accuracy by segment or owner.
5. Recalibrate scoring, stage probabilities, and process rules on a schedule; compare changes to a baseline.

## Output and decision record

Return definitions, routing and handoff contract, data-quality findings, forecast method, evidence/hypothesis table, baseline and measurable targets, process cost, owners, and review date.

## Uncertainty and failure handling

Do not treat a score or dashboard as truth without validating it against outcomes. Mark attribution and sample limitations; if teams dispute definitions, resolve the observable event before changing the report.

## Routing boundaries

Use this skill only for its stated capability and required context. For adjacent work, select a more specific skill from `skill-index.tsv`; do not infer coverage from this department folder or use this skill to authorize actions outside its scope.

## Never

- Require CRM fields that no decision uses.
- Collapse fit and intent into an unexplained score.
- Forecast a deal without a date, next step, and evidence for its stage.
