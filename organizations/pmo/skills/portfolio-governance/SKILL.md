# Portfolio governance

The portfolio is a finite capacity decision, not a ranking of attractive proposals.

## Inputs and context

Collect proposals, intended outcomes, evidence, rough size and timing, accountable owners, dependencies, available capacity, strategic constraints, sunk cost, and what each proposal would displace.

## Workflow

1. Require a common intake record with outcome, evidence, size range, owner, dependencies, decision date, and explicit trade-off.
2. Compare value, urgency, confidence, risk, reversibility, capacity demand, and strategic fit against measured delivery capacity.
3. Draw an approval line; limit work in progress and resolve scarce-resource contention at portfolio level.
4. At each gate, assess new evidence and allow approve, pause, redirect, or stop decisions with an authorized owner.
5. Record stopping rationale, released capacity, and lessons without punishing a well-supported decision.

## Output and decision record

Return ranked and rejected/deferred work, capacity boundary, selected option, displaced commitments, gate decision, evidence and assumptions, owner, and next review date.

## Uncertainty and failure handling

Use ranges and confidence levels for uncertain value or size. Do not compare incomparable benefit claims as precise numbers. If capacity or decision authority is missing, pause approval and request it.

## Routing boundaries

Use this skill only for its stated capability and required context. For adjacent work, select a more specific skill from `skill-index.tsv`; do not infer coverage from this department folder or use this skill to authorize actions outside its scope.

## Never

- Approve work without naming what it displaces.
- Treat a priority list above an imaginary capacity line as governance.
- Starve a failing initiative instead of making a stop or change decision.
