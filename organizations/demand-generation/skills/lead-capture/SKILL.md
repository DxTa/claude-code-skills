# Lead capture

Earn contact information by delivering value and matching the ask to buying readiness.

## Inputs and context

Gather audience and journey stage, acquisition source, proposed asset or tool, value delivered before the form, qualification need, consent requirements, form fields, device mix, current conversion, and follow-up capacity.

## Workflow

1. Define the problem the asset solves and the smallest useful result delivered before asking for contact details.
2. Decide open versus gated from buyer value, sharing and citation needs, qualification value, and privacy expectations.
3. Build a practical template, calculator, checklist, or tool tied to a stage-appropriate next action.
4. Request only fields needed for that next step, explain unusual fields, and record clear consent where follow-up requires it.
5. Trigger overlays from behavior, remember dismissal, preserve mobile usability, and make the close action obvious.
6. Measure qualified completion, asset use, downstream conversion, unsubscribe or complaint rate, and contact quality.

## Output / decision record

Return audience and stage, asset promise, gate rationale, form schema, consent and retention notes, overlay behavior, qualification path, funnel metrics, test hypothesis, and stop condition.

## Uncertainty and failure handling

If the asset attracts low-intent contacts, narrow the promise or change the follow-up rather than adding fields blindly. Test the value and form separately. Route privacy or consent questions to the responsible legal reviewer.

## Routing boundaries

Use this skill only for its stated capability and required context. For adjacent work, select a more specific skill from `skill-index.tsv`; do not infer coverage from this department folder or use this skill to authorize actions outside its scope.

## Never

- Hide broadly useful information solely to collect an email.
- Gate value before demonstrating what the person receives.
- Collect fields or send follow-up without a stated purpose and valid permission.
